# Compatibility / 兼容范围

Version 0.7.1 is a Windows preview requiring Node.js 22+. The underlying native Desktop and SDK integration was exercised with DeepSeek Harness 0.2.2-rc.3 during local 0.5.0 validation; first-run/public packaging was checked in 0.6.0. Project permissions, preflight, compact supervision and staging have model-free contract/package tests. On 2026-11-16, the same supported Windows installation also passed a real new native conversation: fresh MCP discovery, inherited full-access permission, PowerShell write with independent readback, business-question roundtrip with zero permission approvals, disconnect/reconnect and same-session continuation after policy reset. The conversation and full-access status were observed in the Desktop UI. This is bounded native Desktop evidence, not SDK full-access acceptance, another physical computer, a human sign-off or a claim about all models. ACP full access remains refused pending verification. Application buildCommit prefix `6b729` is descriptive, not an allowlist: setup checks the full supported installation identity. Other application builds, SDK versions and operating systems are unverified.

0.7.1为Windows预览版，要求Node22+。2026-11-16在同一受支持的Harness 0.2.2-rc.3安装上，通过新原生对话实测MCP工具发现、继承完全访问、PowerShell真实写入与主控独立读回、无权限审批的业务提问回传、断线重连、项目默认重置后原会话续聊；桌面界面已观察到该对话与完全权限状态。该证据限于本次原生桌面入口，不代签SDK完全访问、所有模型、第二台电脑或真人签收；ACP完全访问仍待验证并拒绝。合同/打包测试继续单独记账。buildCommit前缀6b729不是准入规则，setup按完整支持身份核验。其他系统/版本未验证。

The bridge consumes native Host Workspace Registry and Session Controller services through a bounded local plugin. Internal APIs may change across Harness releases. A source build, installed snapshot, loaded Host plugin, MCP discovery, real model execution and visible UI are separate checks. Do not infer compatibility from matching version labels alone or bypass fingerprint rejection.

Desktop is the default new-conversation route. SDK and ACP are explicit alternatives, not fallbacks. ACP has one-shot permission requests but no blocking user-question operation. A working installation and existing tasks are not upgraded or restarted by publishing this source release.

Fixture tests verify local contracts; real integrations require a compatible installed application, model access and explicit bounded authorization. No private machine verification records or credentials are distributed. Human acceptance is never inferred from test counts.
